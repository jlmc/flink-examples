# Stateful Operators

## 2. Keyed State

No `keyed-state/KeyedStateAdtExample` são demonstrados os principais tipos de estado keyed:

- `ValueState<T>`: armazena um único valor por chave (ex.: contador total por `facilityId`).
- `ListState<T>`: mantém coleção incremental por chave (ex.: histórico de tipos de evento sem reescrever estrutura inteira).
- `MapState<UK, UV>`: mantém pares chave-valor por entidade (ex.: contadores por `eventType` como `ADT_A01`, `ADT_A02`, `ADT_A03`).
- `ReducingState<T>`: aplica redução incremental à medida que os eventos chegam, reduzindo overhead de memória.
- `AggregatingState<IN, OUT>`: agrega com tipo de entrada/saída diferente para criar resumos customizados (ex.: total + admissões).

Mecanismo interno importante:

- após `keyBy`, o Flink garante que todos os eventos de uma mesma chave são processados pela mesma subtask, permitindo isolamento de estado por entidade;
- o acesso ao estado keyed é feito no contexto da chave atual (não há partilha direta entre chaves);
- a escolha entre os tipos de estado afeta footprint de memória e custo de serialização.

### State Time to Live (TTL)

O exemplo ativa TTL no `ValueState` com 30 minutos:

- evita retenção infinita de estado em workloads longos;
- reduz consumo de memória/disco;
- é essencial para fluxos contínuos com chaves de baixa frequência.

Em Flink 1.20.3, o TTL é uma proteção crítica para evitar crescimento ilimitado do estado em jobs de longa duração. Com a política correta, registos inativos podem expirar automaticamente (ex.: 24h sem atualização), reduzindo custos operacionais e risco de pressão de memória/disco.
