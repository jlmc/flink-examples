# Stateful Operators

## 3. Operator & Broadcast State

No submódulo `operator-and-broadcast-state`:

- `Operator State`: usado na source stateful (`StatefulAdtSource`) para guardar o progresso (`nextIdx`) entre checkpoints.
- `Broadcast State`: usado para distribuir regras de negócio (`ADT_A01 -> ADMISSION`, etc.) para todas as subtasks.
- `Stateful Source Function`: a source implementa `CheckpointedFunction` para restaurar continuidade após falha.

Detalhes técnicos relevantes:

- **Operator State** não depende de `keyBy` e é mantido por instância paralela do operador; em mudanças de paralelismo, o estado é redistribuído segundo a estratégia definida (tipicamente lista repartida).
- **Broadcast State** replica um fluxo de configuração/regras para todas as subtasks, permitindo avaliação consistente de regras dinâmicas no fluxo principal.
- **CheckpointedFunction** expõe o ciclo `snapshotState`/`initializeState`, permitindo que variáveis locais da função participem da semântica de fault tolerance do Flink.

### Porque é importante

- `Operator State` resolve estado local de operador (ex.: offsets/progresso interno).
- `Broadcast State` garante consistência de regras globais em processamento distribuído.
- juntos, permitem pipelines resilientes e com lógica dinâmica.
