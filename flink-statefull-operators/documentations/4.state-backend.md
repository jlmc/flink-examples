# Stateful Operators

## 4. State Backend

No submódulo `state-backend`, o exemplo mostra duas configurações comuns:

- `HashMapStateBackend`
  - estado em memória no TaskManager;
  - simples e rápido para estados menores.
  - perfil de menor latência de acesso, desde que o estado caiba em RAM.
- `EmbeddedRocksDBStateBackend`
  - estado persistido localmente em RocksDB (disco);
  - melhor para grandes volumes de estado.
  - suporta estado maior que memória (spill para disco local).

Ambas as opções no exemplo são configuradas com checkpointing ativo e checkpoint storage explícito.

Detalhes técnicos aprofundados (1.20.3):

- **HashMapStateBackend**
  - estrutura de estado em objetos Java na heap;
  - excelente throughput para estados pequenos/médios;
  - limitação prática: crescimento de estado restrito ao orçamento de memória da TaskManager.
- **EmbeddedRocksDBStateBackend**
  - estado em KV store embebida (RocksDB) no disco local da TaskManager;
  - melhor para workloads com estado muito grande (incluindo cenários de TB);
  - permite **checkpoints incrementais**, enviando deltas desde o checkpoint anterior e reduzindo custo de snapshot em estados grandes.

Exemplos implementados:

- `state-backend/HashMapStateBackendAdtExample`
- `state-backend/EmbeddedRocksDbStateBackendAdtExample`

### Configuração prática para S3 (MinIO)

Usando o job `patient-adt-processing-job-maven` como referência, o padrão local recomendado é:

- `HashMapStateBackend` para estado de trabalho em memória;
- checkpoint storage em S3 compatível (`MinIO`) para durabilidade dos snapshots;
- savepoints também em S3 para operações de upgrade/migração.

Exemplo Java (Flink 1.20.3):

```java
Configuration runtimeConfig = new Configuration();
runtimeConfig.set(CheckpointingOptions.SAVEPOINT_DIRECTORY, "s3://flink-s3-bucket/patient-adt/savepoints");
env.configure(runtimeConfig);

env.setStateBackend(new HashMapStateBackend());
env.getCheckpointConfig().setCheckpointStorage("s3://flink-s3-bucket/patient-adt/checkpoints");
```

No `docker-compose` local, o runtime Flink deve ter as propriedades S3:

- `fs.allowed-fallback-filesystems: s3`
- `fs.s3a.endpoint: http://minio:9000`
- `fs.s3a.access.key: minio`
- `fs.s3a.secret.key: minio123`
- `fs.s3a.path.style.access: true`

Isto permite usar URIs `s3://...` no Flink mesmo com MinIO local.
