# Stateful Operators

## 5. Checkpointing e Fault Tolerance

No Flink, a semântica de **Exactly-Once** depende da combinação entre snapshots de estado e coordenação do fluxo por barreiras de checkpoint.

### Snapshots e Barriers

- o JobManager coordena checkpoints periódicos;
- barreiras são injetadas no stream e propagadas entre operadores;
- ao receber a barreira do checkpoint `N`, o operador cria snapshot consistente do estado local;
- após persistência no checkpoint storage (filesystem/S3/HDFS), o checkpoint é considerado concluído.

Em caso de falha, o job é restaurado para o último checkpoint completo, retomando processamento com estado consistente.

### Alinhamento de barreiras

Em operadores com múltiplas entradas, historicamente era necessário alinhar barreiras: esperar a barreira de todas as entradas antes de avançar. Isto pode introduzir pausas quando há assimetria de tráfego entre canais.

Na linha 1.20.x, melhorias no mecanismo reduzem impacto operacional e ajudam a minimizar interrupções perceptíveis no throughput durante o checkpoint.

### Unaligned Checkpoints

Para cenários com **backpressure**, os unaligned checkpoints permitem que a barreira avance sem bloquear totalmente à espera de drenagem completa dos buffers.

Benefícios práticos:

- maior previsibilidade de duração de checkpoint sob congestionamento;
- menor risco de timeout de checkpoint em pipelines pressionados;
- recuperação consistente mesmo em cargas elevadas.

### Configuração recomendada (S3/MinIO)

No `patient-adt-processing-job-maven`, uma configuração robusta para desenvolvimento local com MinIO é:

```java
env.enableCheckpointing(30_000L, CheckpointingMode.EXACTLY_ONCE);
env.getCheckpointConfig().setCheckpointStorage("s3://flink-s3-bucket/patient-adt/checkpoints");
env.getCheckpointConfig().setMinPauseBetweenCheckpoints(10_000L);
env.getCheckpointConfig().setCheckpointTimeout(120_000L);
env.getCheckpointConfig().setTolerableCheckpointFailureNumber(3);
env.getCheckpointConfig().setMaxConcurrentCheckpoints(1);
env.getCheckpointConfig().enableExternalizedCheckpoints(
    CheckpointConfig.ExternalizedCheckpointCleanup.RETAIN_ON_CANCELLATION
);
env.getCheckpointConfig().enableUnalignedCheckpoints();
```

Notas operacionais:

- **Storage durável:** checkpoints ficam em `s3://...` (MinIO local), não no disco efémero do container.
- **Cancelamento seguro:** externalized checkpoints retidos para recuperação manual (`flink run -s <checkpoint>`).
- **Backpressure:** unaligned checkpoints ajudam a reduzir timeouts durante congestionamento.
- **Savepoints:** usar diretório dedicado (`s3://flink-s3-bucket/patient-adt/savepoints`) para lifecycle de deploy.

### Watermarks no pipeline ADT

Para eventos ADT fora de ordem, use `forBoundedOutOfOrderness` com o `eventTimestamp` do evento:

```java
WatermarkStrategy<Tuple2<String, AdtEvent>> watermarkStrategy = WatermarkStrategy
    .<Tuple2<String, AdtEvent>>forBoundedOutOfOrderness(Duration.ofMillis(5_000L))
    .withTimestampAssigner((value, timestamp) -> {
        AdtEvent event = value.f1;
        if (event == null || event.getEventTimestamp() == null) {
            return timestamp;
        }
        return event.getEventTimestamp().toEpochMilli();
    });
```

Isto melhora a semântica temporal do job vs `noWatermarks()` e mantém tolerância controlada a atraso de eventos.
